# Lab 4：定位、控制与路径规划

这次实验是在连续的物理环境中控制 Pacman。和 Lab 1 的网格移动不同，这里的 Pacman 有位置和速度，移动时还要考虑墙体碰撞。

## Part 1：粒子滤波

粒子滤波用很多带权重的粒子估计 Pacman 的位置。我的实现流程是：

1. 在没有墙的位置随机生成粒子；
2. 根据 Pacman 的移动距离和转角更新每个粒子；
3. 比较粒子的模拟传感器读数和真实读数；
4. 误差越小，粒子的权重越大；
5. 按照权重重新采样，并加入少量位置和角度噪声。

代码还会检查粒子是否撞墙。如果所有权重都失效，就重新生成一批均匀粒子，避免程序继续使用错误结果。

## Part 2：PD 控制

PD 控制器的公式是：

```text
F = kp · (target_position - current_position) - kd · current_velocity
```

前一项把 Pacman 拉向目标，后一项根据当前速度进行减速，避免冲过目标后反复振荡。实际效果很依赖 `kp` 和 `kd`，参数太大容易撞墙，太小又会移动得很慢。

## Part 3：RRT 路径规划

我的实现使用双向 RRT-Connect：一棵树从起点生长，另一棵树从终点生长，两边轮流扩展并尝试连接。

为了让它在这个地图里更稳定，我还加入了：

- 一定概率直接向终点或终点附近采样；
- 检查新线段是否穿过墙；
- 两棵树连接成功后合并路径；
- 删除可以直接连通的多余路径点；
- Pacman 卡住时重新规划。

## 路径跟踪

找到路径以后，PD 控制器会依次跟踪路径点。我没有简单地每隔固定时间切换目标，而是根据 Pacman 与路径点的距离判断是否已经到达。

另外还限制了前视距离。目标点选得太远时，PD 控制器可能试图直接穿过墙；只选择附近且能直达的路径点会稳定很多。如果 Pacman 长时间没有接近目标，代码会重新规划，而不是一直卡在原来的路径上。

## 这次实验的收获

这次实验最直接的感受是，规划算法输出一条“数学上不撞墙的路径”还不够。真实执行时有速度和惯性，路径点太密、太远或者靠墙太近都会出问题。定位、规划和控制必须配合调试，不能只看其中一个算法。
