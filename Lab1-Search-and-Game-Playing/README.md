# Lab 1：搜索与博弈

这次实验使用 Pacman 框架，分成经典搜索和多智能体博弈两部分。

## Part 1：经典搜索

### DFS、BFS、UCS 和 A*

我实现了四种搜索算法：

- DFS 用栈，先沿一条路一直往下走；
- BFS 用队列，按离起点的步数逐层搜索；
- UCS 每次选择当前总代价最小的节点；
- A* 在总代价之外加入启发函数，优先搜索更可能接近终点的方向。

写的时候比较容易出错的是判重。BFS 可以在节点进入队列时标记 visited；UCS 和 A* 还需要维护路径代价，否则可能错过后来找到的更短路径。

A* 中的状态有时不是一个坐标，而是 `(当前位置, 已访问目标)`。列表不能直接作为字典的 key，所以我在判重时把它转成了 tuple。

### 角点问题

这道题要求 Pacman 走遍地图的四个角。我把状态写成“当前位置 + 已经到过的角”，然后根据还剩几个角，估计当前位置经过它们所需的距离。

启发函数不能随便写得很大。它如果高估剩余距离，A* 就可能失去最优性；但估计得太保守，又起不到减少搜索节点的作用。

`foodHeuristic` 和寻找最近食物的函数在我的提交中没有完成，代码里仍然保留了原来的空实现。

## Part 2：多智能体博弈

### Minimax 和 Alpha-Beta

Minimax 中，Pacman 选择让分数最大的动作，Ghost 选择让分数最小的动作。因为环境里可能有多个 Ghost，所以需要在递归中依次切换 agent，所有 agent 都走完一轮后再增加搜索深度。

Alpha-Beta 与 Minimax 得到的结果相同，只是会提前跳过不可能影响答案的分支。实际写完以后，剪枝的含义比只看伪代码清楚很多：当前分支只要已经比对手已有的选择更差，就没有必要继续往下算。

### MCTS

我实现了 MCTS 的选择、扩展、模拟和回传四个步骤。选择阶段使用 UCT，在“多尝试没走过的动作”和“继续走当前效果较好的动作”之间取平衡。

模拟结果的评分会考虑食物、胶囊、Ghost 距离和游戏胜负。MCTS 不会像固定深度 Minimax 那样把每个分支都完整展开，而是通过多次模拟逐渐找到更值得搜索的动作。

## 这次实验的收获

我以前对搜索算法的印象主要是几段伪代码。这次自己处理状态、父节点、路径代价和判重后，才真正理解这些算法之间的区别。多智能体部分也让我第一次比较完整地写了递归博弈搜索和基于采样的决策算法。
